Only a trusted immediate socket peer can supply one bounded XFF header (2,048 bytes/32 bare-IP hops). `app/rate_limits.py` now locks clock sampling, expiry, admission and quota mutation together. Queues are ordered by last admitted request. Each protected request removes fully inactive clients, prunes the current sliding window, and expires timestamps at the exact boundary. Denials neither add keys/timestamps nor prolong retention. The maximum active client count is explicit (`RATE_MAX_CLIENTS`, default 10,000). At capacity, active quotas are retained and new clients receive the existing 429/error/security/no-store response with rounded-up Retry-After until a complete slot can expire. No eviction resets quota and no rejection map grows. Positive bounded settings cap the default at 10,000 entries/300,000 admitted timestamps, with a maximum configured product of 1,000,000. These are structural bounds, not measured RSS.

Cleanup is deliberately request-driven: an otherwise idle process may retain expired entries until the next protected request, always within capacity. New-client availability is reduced during saturation rather than dropping enforcement. Limits remain process-local, multiply across workers/replicas and reset on restart. This is not a distributed DDoS defense.

### Calculations worth preserving

- Budget templates sum to 100. Matching priorities multiply non-contingency weights by 1.3; the engine renormalizes other categories while preserving the contingency weight. Largest-remainder allocation produces nonnegative integers whose sum equals the requested total. Percentages are rounded to one decimal and per-guest values to two decimals; displayed percentages need not independently sum to exactly 100 because of rounding.
- Timeline offsets are event-specific. Short notice proportionally compresses offsets within the available window; event-today milestones are all due today. This is deterministic scaling, not a dependency/resource scheduling engine.
- Vendor groups use matching budget keys and a shared checklist library; their allowances equal the relevant budget lines. Dietary needs extend catering checklists. Book-by dates are independently scaled and sorted.
- Health starts at 100 and deducts for low per-guest budget, compressed lead time, less than seven days remaining, and large guest counts; scores are clamped to 0–100. Fixed USD-based thresholds, fixed currency multipliers, and formality multipliers are heuristics. Progress, actual bookings, quotes, and payments do not affect the score.
- ICS provides all-day milestones, escaping, CRLF formatting, and UTF-8-aware line folding. It exports computed templates, not user-edited task state.

Timeline and vendor book-by rules can disagree without arithmetic errors: for a wedding with ample lead time, the venue milestone is 250 days before the event, while the vendor group's book-by date is 240 days before. Decide and test one semantic policy before making future consistency claims.

### Gemini, parsing, fallback, and caching

Gemini receives validated event preferences as serialized user-role data, separately from static system instructions. Verified priority keys derive from engine flags, not raw strings. Narrative cannot mutate numeric Plan fields. The adapter retains JSON/text mode, 1400/400 output tokens and the configured SDK timeout; role/config behavior is tested with stubbed transport, not a live provider.

Parsing retains fenced/prose-wrapped single-object compatibility, validates strict provider types/fields before presentation clamping, rejects duplicate/non-finite/oversized/unknown-field output and rejects thin/blank narrative. The legacy minimum remains three useful ideas and nonblank summary/tips. Free-form chat is bounded and checked for exact context/key echoes, but neither path proves semantic truth; display prose is advisory only.

Legacy stateless chat reuses the plan-generation prompt with the four largest budget lines; it lacks full timeline/vendor/completion context and prior turns. Saved-workspace advice instead uses the new full numeric ledger/task/vendor context and structured actions; all finance/task facts are server-rendered. Original keyword fallback remains for nonfinancial offline topics. Neither path claims conversational memory.

Successful Gemini extras are cached for 900 seconds with 256-entry LRU eviction. Keys hash the full request and server date. Failures are not cached; numeric core is recomputed for generation. Cache access is locked, but misses are not coalesced: concurrent identical requests can still make multiple paid model calls. Cache is per process and does not include model/prompt version in the key. No browser API-result cache, service worker or shared cache exists. The new SQLite workspace repository is separate: GET reopens the persisted snapshot directly and never substitutes a cached/generated plan for it.
